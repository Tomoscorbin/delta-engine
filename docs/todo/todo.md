- [ ] Make the application layer backend-agnostic, not just backend-library-free. Today the `backend-imports-stay-in-adapters` contract only forbids importing the `delta`/`pyspark` _packages_; the application layer still hardcodes Delta-family _policy_ — the safe-change rules (`PartitioningChangeNotSupported`, `NonWideningColumnTypeChange`, `NonNullableColumnAdd`, `ColumnMappingRequiredForDrop`) exist because Databricks/Delta rejects those operations, and `application/properties.py` holds the Delta property policy (`DELTA_PROPERTY_POLICY`, `Property`, and the `delta.*` key strings) consumed by `validation.py`, `api/delta_table.py`, and the reader. The layering is sound for now (application is the only layer all three consumers can reach without violating the `adapters|api → application → domain` order), but it means "backend-agnostic" is only half true. The real refactor: `application` holds only the _mechanism_ (how rules run, the `SafetyRule` protocol, how `validate_diff` composes them), and the backend _specifics_ (which rules, which property keys and their restrictions) are injected from the composition root or an adapter-provided port. This must move ALL the backend-flavoured rules and the property policy together — moving only the property pieces just relocates a third of the problem. Larger change, own PR. See the property-ownership spec addendum for why the policy currently lives in application.

- [x] Phase-typed `_TableRun`: considered and DECLINED 2026-07-30. `_TableRun` is a mutable scratch pad whose four accreting fields are `| None`, and two `RuntimeError` guards (`to_report`, `_execute` in `application/engine.py`) assert states the phase ordering already makes unreachable. Typing the phases — `_Unread` / `_Unreadable` / `_Rejected` / `_Planned` / `_Executed`, each phase becoming `tuple[A, ...] -> tuple[B | C, ...]` — deletes both guards and gets write-once enforcement for free, and would cost nothing in tests (`_TableRun` is private to `engine.py`; nothing in `src/` or `tests/` outside it names the type). Declined for three reasons. (1) Terminal runs cannot be dropped — the account reports them, and the blocking fold needs them to know which parents failed — so every phase gains an explicit pass-through arm; the `| None` already *is* the union tag and `if x is None: continue` already *is* that arm, in one line each. (2) Phase types partition runs by progress, while `blocked_by` needs the sequence ordered by dependency *including* the runs that retired early; any partition would have to be reunited in dependency order before both walks, which fights the invariant #302/#303 were built on. (3) `_Planned` vs `_Executed` spends an entire type to remove the one `ExecutionSummary | None` that #303 just made honest. `code-consolidation-review.md` §2 reached the same conclusion for the public types ("Do not introduce one public class per lifecycle phase merely to eliminate `None`"); that note says *public* and `_TableRun` is private, so the letter does not bind, but the reasoning transfers. What survives as a genuine gap: nothing enforces write-once on the scratch pad, and no cheap mechanism for it was found.
